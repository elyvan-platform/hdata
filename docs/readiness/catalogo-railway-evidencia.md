## Diagnóstico e limites

Plano executado nesta tarefa: uma fase de diagnóstico, recuperação da listagem e
registo de evidência, sem alterações à lógica ou à base de dados. O comando
`elyvan new readiness "Catálogo e índices Railway" --dry-run` falhou com exit 127
(CLI ausente); este relatório foi criado manualmente. Não foi possível trocar
modelos; análise e plano precederam a edição.

Validação local: `pnpm install --frozen-lockfile`, `pnpm check`, `pnpm typecheck`,
`pnpm test` e `pnpm build` terminaram com exit 0. Check mantém três avisos
preexistentes na web. Ambiente: Node 22.23.3, pnpm 12.14.0; Node 24 e PostgreSQL
remoto não foram validados. Os testes locais não provam a publicação do acervo.

- O proxy do shell recusa CONNECT ao URL público (403); o conector web conseguiu ler as páginas acima.
- Não existe CLI Railway, remoto Git ou configuração .railway neste clone. Não foram inspecionadas variáveis, logs, PostgreSQL ou migrações remotas. A causa no ambiente continua por determinar.
- O adaptador existente exige catalogSnapshotSchema em JSON; a ficha oficial é HTML. Configurar a ficha como endpoint não resolve a ingestão. Não foi identificado um endpoint oficial JSON compatível.
- A cópia persistente já existe em createCatalogService: mantém o último catálogo válido após falha. Não cria o primeiro catálogo por si; não existe snapshot oficial completo verificado no clone.
- Os totais 484 batismos / 254 casamentos são referências do protótipo, sem exportações recuperadas. Quantidades reais importadas ou publicadas por fonte não foram medidas na base remota. Não se declara que esses registos não existem.
- historical_entry é staging e não alimenta a pesquisa. A promoção requer assentos/revisões e fluxo draft → in_review → validated → published, com direitos conhecidos. Não foi contornado esse fluxo nem alterada qualquer edição humana.
- Nenhuma migração, importação, publicação ou implantação remota foi executada. A aceitação em produção permanece por cumprir.
